# 第七章 Git 版本控制实践记录

## 7.1 仓库初始化

- 使用 `git init -b main` 创建项目仓库；
- 配置本地用户信息（姓名、学号邮箱）；
- 建立标准目录结构：`docs/`、`src/backend/`、`src/frontend/`、`database/`、`tests/`。

## 7.2 提交规范

遵循 Conventional Commits 规范前缀：

| 前缀 | 用途 | 本仓库示例 |
| --- | --- | --- |
| `chore:` | 构建、杂项 | 初始化项目仓库与标准目录结构骨架 |
| `docs:` | 文档变更 | 大作业报告初稿-系统需求分析 |
| `feat:` | 新增功能 | 添加数据库建库建表脚本 |
| `refactor:` | 重构 | 优化目录结构与归档说明 |
| `test:` | 测试 | 添加数据库脚本验证用例 |

## 7.3 迭代记录（20+ 次提交）

本项目共完成 **22 次** 增量提交，覆盖仓库初始化、标准目录结构搭建、报告初稿撰写、数据库脚本与前后端骨架，每次提交均为独立可追溯的版本。提交历史概览（完整 `git log` 截图附于提交材料中）：

| 类别 | 次数 | 代表提交 |
| --- | --- | --- |
| chore | 2 | 初始化仓库骨架、.gitignore |
| docs | 11 | 报告八章节、README、文档索引、提交规范 |
| feat | 7 | 前后端骨架、建库建表、视图/存储过程/触发器、登录页 |
| refactor | 1 | 数据库目录说明整理 |
| test | 1 | 数据库脚本验证用例 |

## 7.4 实践要点

- 每次提交前 `git add` 精确选择变更文件，保持提交原子性；
- 提交信息首行使用规范前缀 + 简短描述；
- 使用 `.gitignore` 排除编译产物与本地配置文件，保持仓库整洁；
- 使用分支管理功能开发与文档维护（main 主分支）。
