# 第一章 系统需求分析

## 1.1 系统开发背景

据调研，六成以上在校大学生有过兼职经历，但传统兼职渠道存在以下突出问题：

- 兼职信息来源分散，难以集中检索；
- 岗位真实性难以保障，存在虚假信息风险；
- 供需双方匹配效率低，招聘流程不规范；
- 缺乏统一的评价与管理机制。

因此，需要构建一个集岗位发布、检索、申请、录用与评价于一体的校园兼职招聘管理平台。

## 1.2 系统目标

- 采用 B/S 架构，面向学生、商家、管理员三类用户；
- 使用数据库高级机制（视图、存储过程、触发器）保证数据完整性与业务一致性；
- 界面美观友好、易于维护、可扩展。

## 1.3 功能需求

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F1 | 注册登录 | 学生 / 商家 / 管理员注册与登录 |
| F2 | 岗位发布 | 商家发布兼职岗位信息 |
| F3 | 岗位审核 | 管理员审核岗位合法性 |
| F4 | 岗位检索 | 学生按条件检索岗位 |
| F5 | 在线申请 | 学生在线申请岗位 |
| F6 | 用户管理 | 管理员管理三类用户 |
| F7 | 评价管理 | 录用后双方互评 |
| F8 | 数据统计 | 岗位 / 申请数据统计 |

## 1.4 非功能需求

- **性能**：页面响应时间 ≤ 3 秒，支持 500 并发在线用户、100 并发请求；
- **安全**：密码 BCrypt 加密存储、RBAC 访问控制、参数化查询防 SQL 注入、数据库定期备份；
- **可用性**：UI 设计遵循统一规范（主色 #2C6CB0，统一字号、布局与交互标准）；
- **兼容性**：支持 Chrome / Firefox / Edge，分辨率 1366×768 及以上。

## 1.5 非功能需求验收标准

| 指标 | 标准 | 验证方式 |
| --- | --- | --- |
| 响应时间 | ≤ 3 秒 | 浏览器开发者工具 |
| 并发能力 | 500 在线 / 100 请求 | JMeter 压测 |
| 密码安全 | BCrypt 加密存储 | 数据库抽查 |
| 访问控制 | RBAC 权限隔离 | 权限用例测试 |
| 防注入 | 参数化查询 | SQL 注入用例 |
| 界面规范 | 主色 / 字号统一 | UI 走查 |
| 浏览器兼容 | 三大主流浏览器 | 多浏览器回归 |
